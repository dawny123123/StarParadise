## 产品定位与愿景

**星星乐园**是一款面向家庭的激励管理系统，通过"任务打卡 + 双货币激励"的游戏化机制，帮助家长引导孩子养成良好习惯。

**一句话定义**：让家长用"看得见的数据"和"摸得着的奖励"，驱动孩子每天进步一点点。

**核心理念**：
- 将日常学习/生活行为量化为可追踪的任务
- 通过即时反馈（打卡奖励）和长期目标（奖励兑换）双重驱动行为改变
- 用数据可视化帮助家长了解孩子的习惯养成进度

## 目标用户画像

### 家长（管理员）
- **使用终端**：PC 管理后台（浏览器访问）
- **核心诉求**：
  - 便捷地为孩子设置每日任务和奖励目标
  - 一目了然地查看孩子的习惯养成数据
  - 灵活地通过积分系统进行正向激励或约束
  - 长期追踪孩子的成长趋势

### 孩子
- **使用终端**：微信小程序 / H5 移动端
- **核心诉求**：
  - 每天清楚知道"今天要做什么"
  - 打卡后获得即时正反馈（金额/积分增长）
  - 看到自己距离心仪奖励越来越近（进度条）
  - 查看自己的"小金库"和积分余额

### 典型家庭场景
家庭中有 2-3 个不同年龄段的孩子（如初中生、小学生、幼儿园），家长希望通过统一系统管理不同孩子的任务与激励。

## 核心业务流程

### 打卡奖励闭环

这是产品最核心的业务流程，将"行为 → 奖励 → 目标"串联成完整闭环：

```
家长设定任务（含奖励金额）
        ↓
孩子每日打卡完成任务
        ↓
  ┌─────┼─────┐
  ↓     ↓     ↓
金钱入账  目标进度  交易记录
(余额+)  (进度+)  (流水+)
  ↓     ↓
  ↓   达成目标 → 兑换奖励
  ↓
钱包查看余额
```

**关键节点说明**：
1. 家长在 PC 端创建任务，设定每次打卡的奖励金额（如"英语背单词，每次 1 元"）
2. 孩子在小程序中勾选完成的任务，提交打卡
3. 系统自动完成：① 金钱入账 ② 奖励目标进度累加 ③ 生成交易流水
4. 当奖励目标进度达到目标金额时，自动标记为"已达成"
5. 孩子可在钱包页查看累积的金额和积分

## 功能模块详解

### 1. 孩子管理

**功能**：管理家庭中的所有孩子信息。

- 每个孩子有独立档案：姓名、年龄、年级、关注重点、头像颜色
- 系统为每个孩子维护：积分余额、金钱余额（通过交易记录计算）
- 首次启动自动创建示例孩子（甜甜、甄甄、欣甜）

**业务意义**：多孩家庭的核心管理单元，所有任务、打卡、奖励、积分均围绕孩子维度展开。

### 2. 任务管理

**功能**：为每个孩子设定每日待完成的行为清单。

| 属性 | 说明 | 示例 |
|------|------|------|
| 任务名称 | 必填，简洁描述 | "英语背单词" |
| 任务描述 | 可选，详细说明 | "每天背10个单词" |
| 奖励金额 | 每次打卡完成后的奖励数值 | 1.0 |
| 奖励单位 | 奖励的计量单位 | "元"或"积分" |
| 启用状态 | 是否激活（停用后不计入统计） | 启用/停用 |

**业务意义**：任务是打卡的前置条件，也是激励的"起点"。合理的任务设定直接影响孩子的参与度和习惯养成效果。

### 3. 打卡系统

**功能**：孩子每日完成任务后进行打卡确认。

- 支持按日期和孩子筛选打卡记录
- 打卡时自动计算奖励并发放
- 打卡同时更新所有未达成的奖励目标进度
- 所有写操作在事务中执行，确保数据一致性

**防重复打卡**：打卡页加载时自动获取当日已打卡记录，已完成任务显示为禁用状态。

**业务意义**：打卡是"行为 → 奖励"的桥梁，也是生成所有统计数据的基础数据源。

### 4. 奖励目标管理

**功能**：为孩子设定需要积攒金额才能兑换的心仪目标。

| 属性 | 说明 | 示例 |
|------|------|------|
| 目标名称 | 想要获得的物品/体验 | "变形金刚玩具" |
| 目标金额 | 需要积攒的总金额 | 50 元 |
| 当前进度 | 已累积的金额（打卡自动累加） | 23 元 |
| 达成状态 | 是否已达到目标金额 | 未达成/已达成 |

**业务意义**：将"即时小额奖励"与"长期大额目标"结合，培养孩子的延迟满足能力和目标感。

### 5. 积分系统

**功能**：家长手动发放或扣减积分，作为即时行为激励工具。

- 积分与金钱独立运作，互不影响
- 积分以整数为单位，金钱以浮点数计算
- 每次加减积分需填写原因（如"表现优秀"、"未完成作业"）
- 积分变动实时更新孩子的积分余额

**业务意义**：积分是家长的"即时干预工具"，适用于无法用打卡量化的行为（如礼貌待人、主动帮忙等），提供更灵活的激励手段。

### 6. 统计分析

**功能**：提供多维度的数据可视化，帮助家长了解孩子的习惯养成效果。

| 指标 | 计算方式 | 意义 |
|------|----------|------|
| 连续打卡天数 | 从今天（或昨天）向前回溯连续有打卡记录的天数 | 衡量习惯坚持程度 |
| 周完成率 | 本周实际完成数 ÷ (活跃任务数 × 本周天数) | 衡量任务完成覆盖度 |
| 30 日趋势 | 最近 30 天每日完成打卡数的折线图 | 观察长期变化趋势 |
| 余额 | 累计收入(earn) - 累计支出(spend) | 了解金钱积累情况 |

**仪表盘**：聚合所有孩子的今日打卡数、活跃任务数、连续打卡天数、周完成率等核心指标，一屏掌握全家情况。

## 双货币激励体系

星星乐园独创"金钱 + 积分"双货币系统，两套系统独立运作、各有侧重：

### 金钱系统（余额）
| 维度 | 说明 |
|------|------|
| **来源** | 打卡完成任务自动获得 |
| **用途** | 兑换奖励目标（如玩具、零食） |
| **单位** | 浮点数（如 1.5 元） |
| **记录** | transactions 表，type = earn/spend |
| **意义** | 将"劳动 → 报酬"具体化，培养财商意识 |

### 积分系统
| 维度 | 说明 |
|------|------|
| **来源** | 家长手动发放（特殊奖励） |
| **用途** | 行为评价信号，可后续扩展兑换 |
| **单位** | 整数（如 +5 分、-3 分） |
| **记录** | points 表 |
| **意义** | 灵活的正向/负向行为干预工具 |

**设计意图**：金钱奖励提供"可感知的实物激励"，积分提供"即时的精神激励"，两者互补形成多层次的正反馈。

## 业务规则与逻辑

### 打卡规则
1. 打卡必须关联一个有效的孩子和一个有效的任务
2. 打卡日期格式为 YYYY-MM-DD
3. 打卡完成（completed=1）且任务有奖励时，自动创建交易记录（type=earn）
4. 打卡完成同时累加该孩子所有未达成奖励目标的进度
5. 当奖励目标的当前进度 ≥ 目标金额时，自动标记为已达成（is_achieved=1）

### 连续打卡计算
- 从今天开始检查是否有打卡记录
- 如果今天无记录，从昨天开始向前回溯
- 逐日检查，直到某天没有打卡记录为止
- 返回连续有记录的天数

### 周完成率计算
- 本周应打次数 = 活跃任务数 × 本周已过天数
- 实际完成次数 = 本周 completed=1 的打卡记录数
- 周完成率 = 实际完成 / 应打次数

### 积分规则
- 积分变动必须为整数，不允许为 0
- 加减积分时同步更新孩子的积分余额
- 需填写变动原因以便追溯

### 任务删除规则
- 删除任务时先删除所有关联的打卡记录，再删除任务本身
- 整个过程在事务中执行，确保数据一致性

## 用户旅程地图

### 旅程一：家长初始化系统

```
首次使用系统
    ↓
系统自动创建示例孩子（甜甜/甄甄/欣甜）和示例任务
    ↓
家长在 PC 管理后台查看仪表盘，确认数据正常
    ↓
根据实际需要，编辑/新增孩子的任务
    ↓
为孩子设定奖励目标（如"变形金刚玩具 ¥50"）
    ↓
告知孩子可以开始每日打卡
```

### 旅程二：孩子每日打卡

```
打开小程序 → 看到首页问候语和今日统计
    ↓
切换到"打卡"Tab
    ↓
选择孩子 → 查看今天的任务列表
    ↓
已完成的任务显示灰色"已完成"标识
    ↓
勾选未完成的任务 → 点击提交打卡
    ↓
系统反馈打卡成功 → 余额和奖励进度自动更新
    ↓
切换到"钱包"Tab 查看金额和积分变化
```

### 旅程三：家长查看数据与激励

```
登录 PC 管理后台 → 仪表盘查看全家概览
    ↓
切换到"数据统计" → 选择某个孩子
    ↓
查看连续打卡天数、周完成率、30 天趋势图
    ↓
发现孩子表现好 → 切换到"积分记录"
    ↓
手动发放积分奖励（如 +5 分，原因："本周全部完成"）
    ↓
孩子小程序端积分余额实时更新
```

### 旅程四：奖励目标达成与兑换

```
孩子每天打卡，奖励目标进度逐渐累积
    ↓
进度条达到 100%，系统自动标记"已达成"
    ↓
家长在线下购买奖励物品给孩子
    ↓
家长在管理后台标记奖励已兑换（更新状态）
    ↓
孩子获得正反馈，设定下一个奖励目标
```
