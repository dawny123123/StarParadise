本模块作为 StarPark（server + pc-admin + miniprogram）之上的编排与验证层，采用声明式配置驱动：`config/environment.json` 集中描述运行时语言/版本、SQLite 数据库路径、Express 服务端口、环境变量及可执行的 `functional_scenarios`（如 health_check、checkin_flow），并通过 `scripts/setup-env.sh`、`start-server.sh`、`teardown-env.sh` 完成依赖安装、后端进程拉起与健康检查轮询。验证流程按四层递进：layer_1_per_task → layer_2_project_build/lint → layer_3_global_verification → layer_4_functional，结果汇总写入 `trace/verification-report.json`，失败用例归档至 `trace/failures/`。每个开发任务以独立目录驻留于 `tasks/<task-id>/`，其中 `state/` 记录 task/context/result 三态 JSON，`checkpoints/` 按子任务编号保存中间产物；`memory/knowledge/` 下的 `domain.json` 与 `conventions.json` 用于沉淀领域事实与编码约定，`memory/episodes/` 存储历史会话回放。依赖方向单向向下：harness 仅通过 HTTP 调用 star-park/server 暴露的 REST API，不直接引用业务代码，从而将验证逻辑与实现解耦。
