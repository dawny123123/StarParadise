## 1. 整体方案

仓库包含两个独立的前端应用，分别服务于家长端（PC 管理后台）和孩子端（uni-app 小程序/H5），二者通过统一的视觉主题保持风格一致。

- **家长端（pc-admin）**：基于 Vue3 + Vite + Element Plus，使用 CSS 变量 + 全局 reset + 组件库主题覆盖的方式组织样式。
- **孩子端（miniprogram）**：基于 uni-app（Vue3 + Vite），使用 SCSS 变量 + `<style lang="scss" scoped>` 的 BEM 命名方式组织样式。

两套前端共享同一套主色调 `#19C8B9`（primary）及子色（`#FF6B6B`、`#4ECDC4`、`#FFD93D`），用于区分不同孩子/卡片，体现“家庭多成员”的业务语义。

## 2. 关键文件

- `star-park/miniprogram/src/uni.scss` — 小程序全局 SCSS 设计令牌（颜色、圆角、阴影）
- `star-park/pc-admin/src/styles/main.css` — PC 端全局 CSS 变量、reset、Element Plus 主题覆盖、通用工具类与动画
- `star-park/miniprogram/src/components/ChildCard.vue` — 小程序侧核心复用组件，展示 BEM 命名 + SCSS 变量的用法
- `star-park/pc-admin/src/views/Dashboard.vue` — PC 端首页，演示 Element Plus 表单/对话框 + 自定义 CSS 变量 + 动画类的组合
- `star-park/pc-admin/package.json` / `star-park/miniprogram/package.json` — 确认依赖：Element Plus、ECharts、Pinia、Vite、Sass、uni-app

## 3. 架构与约定

### 设计令牌（Design Tokens）

| 类别 | 小程序（SCSS 变量） | PC 端（CSS 变量） | 说明 |
|---|---|---|---|
| 主色 | `$primary: #19C8B9` | `--primary: #19C8B9` | 品牌强调色 |
| 浅色变体 | `$primary-light: #E0F7F5` | `--primary-light: #5EDDD2` | hover / 背景 |
| 深色变体 | — | `--primary-dark: #13A89B` | active 态 |
| 背景 | `$bg: #F8F8F0` | `--bg: #F8F8F0` | 页面底色 |
| 文字 | `$text: #725D42` | `--text: #725D42` | 正文色 |
| 辅助文字 | `$text-light: #999999` | `--text-light: #A89880` | 次要信息 |
| 边框 | `$border: #E8E8E8` | — | 分割线 |
| 表面 | `$surface: #FFFFFF` | `--card-bg: #FFFFFF` | 卡片背景 |
| 孩子色 | `$child-1/2/3` | `--child-2/3/4` | 按孩子分配标识色 |
| 圆角 | `$radius-card: 16rpx` | `--border-radius: 18px` | 卡片/按钮圆角 |
| 阴影 | `$shadow-card: 0 2rpx 16rpx rgba(0,0,0,0.06)` | `--shadow: 0 2px 12px rgba(0,0,0,0.08)` | 卡片浮层 |

### 样式组织模式

- **小程序**：每个 `.vue` 组件内以 `<style lang="scss" scoped>` 编写，采用 **BEM 命名**（如 `.child-card__header`、`.child-card__badge--done`），并通过 `@import` 或全局引入 `uni.scss` 中的变量。单位统一使用 `rpx` 适配多端。
- **PC 端**：全局样式集中在 `src/styles/main.css`，定义 `:root` CSS 变量、基础 reset、Element Plus 主题覆盖（通过 `--el-*` 变量）、通用工具类（`.page-container`、`.card`、`.fade-in-up`、`.check-bounce`）。组件级样式仍使用 `<style scoped>` 并引用 CSS 变量。

### 组件库集成

- PC 端使用 **Element Plus**（`element-plus` + `@element-plus/icons-vue`），通过覆盖 `--el-button-bg-color`、`--el-tabs__active-bar`、`--el-switch__core` 等 CSS 变量将默认主题替换为项目主色 `#19C8B9`。
- 图表使用 **ECharts**（`echarts`），在统计页中渲染数据可视化。
- 状态管理使用 **Pinia**（`pinia`），store 中维护颜色池 `colorPool` 供选择孩子头像色。

### 响应式策略

- 小程序端依靠 uni-app 的 `rpx` 单位自动适配不同屏幕宽度。
- PC 端通过 `html, body { min-width: 1024px }` 限制最小宽度，未实现断点媒体查询；布局主要依赖 Flexbox 的 `flex-wrap` 自适应（如 Dashboard 的 `.cards-row`）。

### 动效约定

- 全局定义 `fadeInUp`（页面进入）和 `checkBounce`（打卡成功反馈）两个 keyframes，配合 `.fade-in-up`、`.check-bounce` 工具类复用。
- 卡片悬停通过 `transform: translateY(-2px)` + 加深阴影提供微交互。

## 4. 约定与约束

- **颜色来源**：所有 UI 颜色必须来自 `uni.scss`（小程序）或 `main.css` 的 CSS 变量（PC 端），禁止在组件内硬编码十六进制色值（除业务上动态分配的 child color 外）。
- **命名规范**：小程序组件样式严格遵循 BEM（block__element--modifier），便于在 uni-app 环境中避免样式污染。
- **Element Plus 主题**：所有第三方组件的颜色必须通过覆盖 `--el-*` 变量实现，不得直接写死 `!important` 以外的行内样式。
- **单位规范**：小程序端统一使用 `rpx`；PC 端使用 `px`。
- **卡片/容器**：统一使用 `.card` 工具类（PC 端）或 `$radius-card` + `$shadow-card`（小程序端）包裹内容块，保证一致的圆角与阴影。
- **业务语义色**：`$child-1/2/3` / `--child-2/3/4` 用于区分不同孩子的卡片、头像、进度条，体现“多成员家庭”的业务特征。
- **动画复用**：新增动效应优先复用已有的 `fadeInUp` / `checkBounce`，而非重复定义 keyframes。

## 5. 适用性说明

该样式体系同时覆盖家长端（PC 管理后台）与孩子端（小程序/H5），通过共享的主色与子色体系确保跨端视觉一致性，是本项目前端样式的核心约定。
