本仓库采用分层、多来源的配置加载策略，覆盖运行时服务、前端构建与编排层三个维度：

### 1. 后端服务（Express）
- 环境变量：仅通过 process.env.PORT 读取端口，默认回退到 3001；未使用 dotenv 或集中配置文件。
- 数据库路径：SQLite 文件路径硬编码在 star-park/server/data/star-park.db，由 database.js 自动创建，无外部化配置。
- 健康检查端点：/api/health 作为启动就绪探针，被编排脚本轮询。

### 2. PC 管理前端（Vite + Vue3）
- Vite 环境变量：通过 .env 与 .env.production 提供 VITE_QODERWAKE_INVOKE_URL、VITE_QODERWAKE_PAT 等以 VITE_ 前缀的变量，在 src/api/index.js 中通过 import.meta.env.* 读取。
- 开发代理：vite.config.js 将 /api 代理至 http://localhost:3001，将 /qoderwake-api 重写并转发至 https://api.qoder.com/v1/qoderwake。
- 生产环境差异：.env 与 .env.production 分别定义本地与线上 QoderWake API 地址与 PAT。

### 3. 编排层（Harness）
- 环境声明式配置：harness/config/environment.json 集中描述运行时语言版本、数据库类型与路径、服务端口、测试环境变量、功能场景步骤以及脚本入口。
- Shell 脚本注入：harness/scripts/start-server.sh 通过 export PORT="${PORT:-3001}" 和 export NODE_ENV="${NODE_ENV:-development}" 向子进程注入环境变量；setup-env.sh 负责安装依赖与初始化 SQLite。
- 健康探测：启动脚本循环调用 curl http://localhost:${PORT}/api/health 等待服务就绪。

### 4. 小程序端（UniApp）
- 未发现独立的配置文件或环境变量加载逻辑，API 基础地址可能内联于源码或通过 uni-app 平台配置。

### 开发者约定
- 后端新增可配置项应优先使用 process.env.XXX，并在 harness/config/environment.json 的 test_environment.env_vars 中补充测试值。
- 前端新增 Vite 变量需以 VITE_ 前缀命名，同步更新 .env 与 .env.production，并在 vite.config.js 中维护代理规则。
- 敏感信息（如 PAT）仅存放于各模块的 .env* 文件中，不得提交到版本库。
- 编排层变更需保持 environment.json 与服务实际行为一致，确保 start-server.sh 与 setup-env.sh 能正确驱动应用。
