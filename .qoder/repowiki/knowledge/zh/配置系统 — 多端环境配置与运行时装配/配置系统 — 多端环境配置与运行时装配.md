本仓库采用分层、分模块的配置体系，覆盖后端服务、PC 管理前端、小程序以及 harness 编排层，核心思路是“环境变量 + 构建期常量 + 配置文件”的组合。

1. 后端服务（Express）
- 启动入口 star-park/server/src/index.js 通过 process.env.PORT 读取端口，默认 3001；NODE_ENV 由 harness 脚本注入。
- 应用中间件与路由在 src/app.js 中集中注册，健康检查端点 /api/health 用于就绪探测。
- 数据库使用 better-sqlite3，数据文件位于 star-park/server/data/star-park.db，首次启动自动创建，无需外部数据库服务。
- 无 .env 文件，所有运行时参数通过进程环境变量注入。

2. PC 管理前端（Vite + Vue3）
- 使用 Vite 的 .env 和 .env.production 文件管理构建期常量，变量必须以 VITE_ 前缀暴露给客户端代码。
- vite.config.js 中配置开发代理：/api 转发到 http://localhost:3001，/qoderwake-api 转发到 https://api.qoder.com 并做路径重写。
- 生产构建时通过 .env.production 覆盖 API 地址与 PAT 令牌。

3. 小程序（UniApp + Vite）
- 通过 star-park/miniprogram/vite.config.js 配置开发服务器端口 5175，并将 /api 代理到后端 3001 端口。
- 小程序端未使用 .env 文件，API 地址通过 uni-app 的 manifest.json 或 pages.json 中的 baseUrl 配置（未在本文档范围内验证）。

4. Harness 编排层
- harness/config/environment.json 是统一的运行环境描述文件，声明语言版本、构建/开发/测试命令、SQLite 数据库路径、Express 服务端口、测试环境变量、功能场景与脚本入口。
- harness/scripts/setup-env.sh 负责安装各子项目依赖（server、pc-admin、miniprogram），并输出 SQLite 嵌入式数据库提示。
- harness/scripts/start-server.sh 设置 PORT 与 NODE_ENV 环境变量后启动后端，并通过轮询 /api/health 等待服务就绪。
- harness/scripts/teardown-env.sh 用于清理环境（脚本存在但内容未在此处展示）。

5. 配置约定与约束
- 后端服务完全依赖进程环境变量（PORT、NODE_ENV），不读取 .env 文件。
- 前端构建期配置统一使用 Vite 的 .env* 文件，并以 VITE_ 前缀命名。
- 开发期前后端通过 Vite 代理联调，避免跨域问题。
- 数据库为嵌入式 SQLite，路径在 environment.json 中集中声明，无需额外服务管理。
- 所有可执行脚本通过 set -euo pipefail 保证失败即停，start-server.sh 强制等待健康检查通过后再退出。
