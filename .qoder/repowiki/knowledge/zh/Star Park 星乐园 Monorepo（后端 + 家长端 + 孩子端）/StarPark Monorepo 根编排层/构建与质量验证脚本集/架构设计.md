脚本按职责划分为三类，全部以只读方式访问 star-park/ 源码与 SQLite 数据库，不被业务代码反向引用：
- Python 静态分析器：`lint-deps.py` 基于文件顶部 `LAYERS` 字典（L0 数据层→L5 前端入口）扫描 `.js/.vue/.ts` 中的 `require/import`，强制上层只能导入下层并禁止前后端跨子项目直接导入；`lint-quality.py` 扫描 `console.log` 与文件大小（默认 ≤500 行），通过 `KNOWN_EXCEPTIONS` / `KNOWN_LARGE_FILES` 白名单放行例外。
- Shell 工具脚本：`check-db-consistency.sh` 用 `sqlite3` 校验 children/tasks/checkins/rewards/transactions/points 等核心表及字段存在性；`code-review-check.sh` 禁止 `debugger` 并统计 TODO；`generate-api-doc.sh` 正则扫描 Express 路由定义输出到 `docs/api.md`；`run-api-tests.sh` 通过 `curl` 调用 `/health`、`/children`、`/tasks`、`/dashboard` 做冒烟测试。
- 编排入口：`validate.py` 顺序执行 `make build → make lint-arch → make test → [可选] make verify`，任一阶段失败即中止，支持 `--skip-verify` 跳过端到端验证。
依赖方向单向：所有脚本仅读取源码与数据库，不修改业务逻辑。
