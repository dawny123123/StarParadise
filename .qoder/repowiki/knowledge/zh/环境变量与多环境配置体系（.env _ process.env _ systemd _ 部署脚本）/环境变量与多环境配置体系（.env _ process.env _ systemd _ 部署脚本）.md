## 1. 使用的系统与工具
- 后端（Express/Node.js）：通过 `process.env` 读取运行时配置，无第三方配置库。
- 前端（Vite + Vue3、uni-app）：通过 Vite 的 `import.meta.env.*` 注入以 `VITE_` 为前缀的环境变量；开发期使用 `vite.config.js` 中的 `server.proxy` 将 `/api` 代理到后端。
- 生产部署：由 `deploy/deploy.sh` 生成并加载 `star-park.env` 文件，并通过 systemd unit 启动服务。
- 本地/测试编排：`harness/config/environment.json` 声明数据库类型、端口、环境变量及功能场景，配合 `harness/scripts/*.sh` 启动/停止服务。

## 2. 关键文件
- `star-park/server/src/index.js`：解析 `PORT`，默认 `3001`，作为后端监听端口。
- `star-park/server/src/app.js`：解析 `STATIC_DIR`，若存在则托管 PC 管理后台静态资源并回退到 `index.html`。
- `star-park/server/package.json`：`start`/`dev`/`test` 等脚本入口，依赖 `NODE_ENV` 区分行为（见 harness）。没有 `.env` 文件，全部走进程环境变量。
- `star-park/pc-admin/.env`、`star-park/pc-admin/.env.production`：Vite 构建时注入的 `VITE_QODERWAKE_*` 系列密钥与 API 地址（开发用相对路径，生产用 `https://api.qoder.com`）。
- `star-park/miniprogram/vite.config.js`：开发服务器 `port: 5175`，`/api` 代理到 `http://localhost:3001`。
- `star-park/pc-admin/vite.config.js`：开发服务器 `port: 5174`，`/api` 代理到 `http://localhost:3001`，另将 `/qoderwake-api` 代理到 `https://api.qoder.com` 并重写路径。
- `harness/config/environment.json`：声明 `runtime.build_command`、`databases[0].path`、`services[0].port=3001`、`test_environment.env_vars.NODE_ENV=test, PORT=3002` 等。
- `deploy/deploy.sh`：生产部署脚本，生成并复用 `${SHARED_DIR}/star-park.env`，设置 `NODE_ENV=production`、`PORT=${APP_PORT}`（默认 `3002`）、`STATIC_DIR=${CURRENT_LINK}/pc-admin`。
- `deploy/star-park-server.service`：systemd unit，由 deploy 脚本安装，负责以 root 身份启动服务。

## 3. 架构与约定
- **单一来源**：所有运行期配置均以环境变量形式注入，不维护应用内配置文件。后端仅读取 `process.env.PORT`、`process.env.STATIC_DIR`、`process.env.NODE_ENV`。
- **分层覆盖**：
  - 开发：`vite.config.js` 中硬编码 proxy target `http://localhost:3001`；`.env` 提供 `VITE_*` 变量供前端构建。
  - 测试：`harness/config/environment.json` 指定 `NODE_ENV=test`、`PORT=3002`，由 `harness/scripts/start-server.sh` 加载。
  - 生产：`deploy/deploy.sh` 首次创建 `star-park.env` 后复用，systemd unit 在启动时加载该文件。
- **版本化发布**：`deploy/deploy.sh` 采用 releases 目录 + `current` 软链的原子切换模式，每次部署新建 `releases/<RELEASE_ID>`，数据目录通过软链指向共享 `shared/data`，避免版本切换丢失 SQLite 数据。
- **健康检查集成**：后端暴露 `/api/health` 返回 `{ status: 'ok', timestamp }`；部署脚本在重启后调用 `deploy/health-check.sh` 验证端口可达，失败触发回滚。
- **前端静态资源托管**：生产模式下后端通过 `express.static(STATIC_DIR)` 直接托管 PC 管理后台产物，非 `/api/*` 请求统一回退到 `index.html`，无需 nginx。

## 4. 约定与约束
- 后端端口：开发默认 `3001`（`src/index.js`），生产默认 `3002`（`deploy/deploy.sh` 注释说明 3001 被无关线上应用占用，勿改回）。
- 环境变量命名：
  - 后端：纯 `process.env` 键名（`PORT`、`STATIC_DIR`、`NODE_ENV`）。
  - 前端：必须以 `VITE_` 开头才能在 Vite 构建期注入（如 `VITE_QODERWAKE_INVOKE_URL`）。
- 敏感信息：`.env` 中的 Qoder PAT 等密钥随仓库提交，未使用外部 secrets 管理；生产通过 `chmod 600 star-park.env` 限制权限。
- 数据库路径：由 `harness/config/environment.json` 声明 `better-sqlite3` 驱动与 `star-park/server/data/star-park.db` 路径；生产部署时通过软链 `releases/*/server/data -> shared/data` 实现跨版本持久化。
- 部署安全守卫：`deploy/deploy.sh` 在部署前检查端口占用，若非本服务持有则拒绝部署，防止误杀其他线上进程。
- 回滚策略：部署失败自动回滚到上一个 release，若回滚后健康检查仍失败则输出 critical 日志并需人工介入；保留最近 5 个版本用于清理。
- 构建命令约定：`npm run dev` 使用 `node --watch` 热重载；`npm start` 启动生产服务；测试通过 `vitest run` 执行，测试环境强制 `NODE_ENV=test`。
