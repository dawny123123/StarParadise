本项目采用基于 Makefile 的统一入口与各子模块独立 package.json 的 monorepo 构建体系，后端、PC 管理端与小程序各自维护依赖与构建脚本，通过顶层 Makefile 和 harness/ 下的 shell 脚本进行环境编排与验证。

**1. 使用的系统与工具**
- 顶层构建入口：Makefile，提供 build、test、api-doc、check-db、api-test、check-conventions、lint-arch、verify、setup-env、start-server、teardown-env 等目标。
- 包管理与脚本：每个子模块使用 npm scripts（star-park/package.json 聚合安装与启动）。
- 后端构建与测试：Express + Node.js，使用 vitest（v8 覆盖率）运行单元测试，supertest 做 HTTP 集成测试。
- PC 管理端构建：Vue3 + Vite，vite build 输出静态资源。
- 小程序构建：UniApp CLI (uni)，支持 mp-weixin 与 H5 双端构建。
- 辅助脚本：scripts/ 下存放 API 文档生成、数据库一致性检查、API 端到端测试、编码规范检查等 shell 脚本；harness/scripts/ 负责环境准备、服务启停与清理。

**2. 关键文件与位置**
- 顶层编排：Makefile
- 子模块清单与脚本：star-park/package.json、star-park/server/package.json、star-park/pc-admin/package.json、star-park/miniprogram/package.json
- 构建配置：star-park/pc-admin/vite.config.js、star-park/miniprogram/vite.config.js、star-park/server/vitest.config.js
- 开发期脚本：scripts/generate-api-doc.sh、scripts/check-db-consistency.sh、scripts/run-api-tests.sh、scripts/code-review-check.sh
- 环境编排：harness/scripts/setup-env.sh、harness/scripts/start-server.sh、harness/scripts/teardown-env.sh

**3. 架构与约定**
- Monorepo 结构以 star-park/ 为应用根，包含 server、pc-admin、miniprogram 三个独立 npm 项目，共享顶层 Makefile 作为统一命令入口。
- 后端使用嵌入式 SQLite（better-sqlite3），无需外部数据库服务，由 database.js 首次启动时自动建库，check-db-consistency.sh 校验核心表与字段存在性。
- 前端开发服务器通过 Vite proxy 将 /api 请求转发至 http://localhost:3001，与后端端口解耦。
- 版本策略：各子模块在 package.json 中独立声明 version: 1.0.0，无统一的版本号同步机制。
- 测试分层：后端单元测试（vitest）、HTTP 集成测试（supertest）、API 端到端测试（curl 脚本）、代码质量检查（grep 规则）共同构成验证链。

**4. 约定与约束**
- 所有构建与验证命令通过 make <target> 调用，新增脚本应遵循 scripts/*.sh 命名并返回非零退出码表示失败。
- 环境变量通过 harness/scripts/start-server.sh 注入（PORT、NODE_ENV），默认端口 3001。
- 编码规范检查强制禁止 debugger 语句，对 TODO 标记仅做提醒不阻断。
- API 文档通过扫描 star-park/server/src/routes/ 中的路由定义自动生成至 docs/api.md。
- 数据库 DDL 与实体字段一致性由 check-db-consistency.sh 显式校验 children/tasks/checkins/rewards/transactions/points 等核心表。
- 未引入 Dockerfile 或 CI 流水线配置文件，构建与部署目前依赖本地 Makefile 与 shell 脚本。
